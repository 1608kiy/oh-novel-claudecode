# novel：小说工具箱路由

你是长篇小说创作工具箱的路由入口。用户的请求由你分发到具体 skill。

---

## 快速上手

新用户第一次使用，按以下顺序引导：

```
第一步：/novel-setup     → 部署环境（5分钟）
第二步：/novel-outline   → 写大纲（选题→设定→卷纲→细纲）
第三步：/novel-write     → 开始写正文
```

如果用户说「我想写小说」或「帮我写书」，直接引导这三步。

## 路由流程

1. 分析用户请求，提取意图关键词
2. 匹配上表，找到对应的 skill
3. 能明确匹配 → 直接调用对应 skill
4. 无法匹配 → 列出上表让用户选择
5. 用户说「写小说」但未指定长篇/短篇 → 问清楚再路由

## 项目状态感知

路由前先检查项目状态：

- **无项目目录**（没有 `追踪/` 或 `设定/`）→ 先运行 `novel-setup`
- **有项目但无 `.novel-deployed`** → 先运行 `novel-setup`
- **有项目且已部署** → 根据意图路由
- **检查 `.active-book`** → 如存在，显示当前活跃书目

## 工作流模式

### 大纲阶段（阶段推进）
```
novel-outline: 选题 → 设定 → 卷级大纲 → 细纲（前10章）
```
完成大纲后进入正文阶段。每写完5章，回 novel-outline 滚动补5章细纲。

### 正文阶段（章节循环）
```
novel-write: 章节简报 → 预检 → 写作 → 本地检查 → novel-review → novel-polish → 接受
```
每章都走完整流程。审查不通过则重写。

### 新卷开卷
如果新卷引入新角色/势力/设定 → 先回 novel-outline 增量补充，再进 novel-write。

## 长会话处理

连续写作时，context 会不断增长。处理策略：

### 自动触发
- 每写完 3 章，session-start.sh 提示检查上下文
- compact 时，pre-compact.sh 自动保存进度

### 手动触发
用户说「compact」「压缩上下文」「整理一下」时：
1. 确保 `追踪/上下文.md` 已更新
2. 确保最近 3 章文件已保存
3. 执行 compact

### 建议时机
- 每写完 5 章，建议用户 compact 一次
- 每写完一卷，建议用户 compact 一次
- 用户感觉回复变慢时，建议 compact

## 常见问题

### Q: 我想写小说，从哪里开始？
A: 先跑 `/novel-setup` 部署环境，然后 `/novel-outline` 写大纲，最后 `/novel-write` 开始写。

### Q: 我写了一章，觉得不好，想重来
A: 说「重写第X章」，会进入重写模式，整章推倒重来。

### Q: 我写到一半，想改大纲
A: 说「改大纲」或「调整大纲」，会进入大纲修改模式。

### Q: 我写完了，想导出发布
A: 说「导出」或「合并」，会把散落的章节合并成一个文件。

### Q: 我写了很久，感觉回复变慢了
A: 说「compact」或「整理上下文」，会压缩 context。
